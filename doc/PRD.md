# SOSMET — PRODUCT IDENTITY

## Name

**Sosmet**

Short for **Social Media**.

The name should feel casual, familiar, and slightly playful. It should not communicate “AI product” directly.

Users should naturally be able to say:

- “upload di Sosmet”
- “cek Sosmet dulu”
- “dia nge-like post gue di Sosmet”
- “followers gue naik”

The product should feel like an actual social app rather than a technology demo.

---

# Platform

Sosmet is a **mobile-first Progressive Web App (PWA)**.

Primary target:
- mobile browser
- installed PWA
- desktop browser as secondary experience

## PWA Requirements

The app should support:

- installable PWA
- app-like standalone display
- responsive mobile layout
- responsive desktop fallback
- fast initial load
- offline-friendly shell where practical
- persistent session
- image upload from mobile gallery/camera
- mobile-safe-area handling
- touch-friendly controls
- lightweight transitions
- app icon
- splash/loading experience appropriate for PWA

The application should feel like:

> “I installed a social media app.”

Not:

> “I opened a website.”

---

# Brand Direction

## Brand Personality

Sosmet should feel:

- casual
- social
- visual
- youthful
- slightly playful
- clean
- familiar
- understated

It should NOT feel:

- corporate
- futuristic
- overly luxurious
- obviously AI
- overly gamified
- like a developer experiment

## Visual Identity

Prioritize:

- white / neutral surfaces
- strong photography
- simple typography
- subtle borders
- restrained iconography
- generous spacing
- minimal visual noise

The UI should be recognizable without relying on Instagram's exact design.

---

# AI Visibility Principle

AI should be primarily invisible.

Do NOT prominently display:

- “AI Comment”
- “AI User”
- “Generated by AI”
- robot icons
- AI badges
- chatbot-style interfaces

Synthetic accounts should behave like ordinary accounts inside the sandbox.

The user experience should focus on:

**people → posts → interactions → social dynamics**

rather than:

**AI → prompts → generations → tokens**

Developer/debug information may expose the simulation system separately.

---

# Social World

Sosmet should not feel like a collection of random fake accounts.

It should feel like a **small interconnected social world**.

Synthetic accounts can:

- follow each other
- like each other's posts
- comment
- discover new accounts
- develop repeated interactions
- form interest clusters
- post content
- occasionally disappear or become inactive

The user's account is inserted into this existing world.

This means the world should exist independently of the user.

---

# Initial World Seeding

On first launch, the application should have an initial synthetic population.

For example:

- 50–200 synthetic accounts for MVP
- multiple content niches
- different activity levels
- different follower counts
- different posting frequencies
- existing social relationships

Avoid creating accounts that look like obvious placeholders:

Bad:
- user001
- user002
- ai_girl_01
- test_account_34

Better:
- coherent usernames
- believable bios
- consistent profile photos
- consistent interests
- consistent posting behavior

---

# User Onboarding

Keep onboarding extremely lightweight.

Potential flow:

1. Choose username
2. Add profile picture
3. Add optional bio
4. Choose a few interests
5. Enter Sosmet

Interests may be used to personalize:

- initial feed
- recommendations
- synthetic accounts shown
- probability of interaction

Do not turn onboarding into a long questionnaire.

---

# First Session

The first session should immediately demonstrate that Sosmet is alive.

The user should be able to:

1. enter the feed
2. see existing posts
3. discover accounts
4. follow a few people
5. upload their first post
6. eventually receive organic-looking interaction

Avoid immediately giving the user fake “WELCOME! 10 LIKES!” engagement.

Let the world breathe.

---

# Engagement Philosophy

Sosmet should intentionally contain **uneven engagement**.

Examples:

Post A:
- 1 like
- 0 comments

Post B:
- 8 likes
- 1 comment

Post C:
- 2 likes
- 0 comments

Post D:
- unexpectedly gets 25 likes

This creates uncertainty.

The user should not be able to reverse-engineer:

> “Every post gives me exactly 5 likes.”

---

# Human-Like Imperfection

Synthetic behavior should contain imperfections.

Examples:

- someone likes an old post
- someone comments but doesn't follow
- someone follows without interacting
- someone repeatedly likes posts but rarely comments
- someone disappears for several days
- an account posts at unusual times
- a post receives engagement hours after posting
- some comments are slightly awkward
- some posts receive no engagement

Perfect behavior looks fake.

Small inconsistencies make the world believable.

---

# Social Feedback Loop

Sosmet should allow a feedback loop:

User posts
↓
synthetic accounts discover post
↓
some interact
↓
profile receives visits
↓
some accounts follow
↓
new social relationships form
↓
future posts receive different distribution
↓
user's social graph evolves

The system should therefore have memory.

---

# Post Intelligence

Each post can maintain two layers of information:

### Human-facing

- image
- caption
- timestamp
- engagement

### System-facing

- visual metadata
- content topics
- detected scene
- estimated mood
- objects/entities
- content category
- embedding or semantic representation
- interaction history

The system-facing layer should never need to be exposed in the normal UI.

---

# Cost Efficiency

AI calls should be treated as an expensive resource.

Never use an LLM for every social event.

Preferred hierarchy:

### No LLM

Use normal code/probability for:
- views
- likes
- follows
- feed ranking
- activity timing
- follower growth
- notification events

### Lightweight LLM

Use for:
- comments
- captions
- small personality-driven interactions

### Vision model

Use once per uploaded image to create structured visual metadata.

Then reuse that metadata.

Goal:

> Maximum perceived intelligence per AI call.

---

# Simulation vs Generation

Important distinction:

**Simulation decides WHAT happens.**

**Generative AI decides HOW it is expressed.**

Example:

Simulation:
> @naya has a 12% probability of commenting.

If the event happens:

Generative AI:
> produces a contextually appropriate comment.

This prevents the LLM from becoming the actual social engine.

---

# Future Possibility

The long-term vision could expand from:

**photo social app**

into:

**persistent synthetic social world.**

Potential future systems:

- communities
- trends
- friendships
- creator ecosystems
- social status
- niche cultures
- viral events
- collective conversations
- evolving social graph

But these should not be part of MVP unless they materially improve the core experience.

---

# Product North Star

Sosmet should feel like a place where:

> **people post things, other people notice, and the social world moves on.**

The technology should disappear into the experience.
